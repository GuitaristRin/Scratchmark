# M13 实验规格：笔型尺寸预置

状态：Canon，仅约束当前实验。SDK 0.13.0，ABI 1，快照格式仍为 1 / 2 / 3；M0–M12 的既有接口与行为保持不变。不承诺稳定发布兼容。

## 背景与能力位

主流移动便签有“笔型 × 尺寸档位”的模型：`Paint.Type { PENCIL, MARK, BALLPEN, PEN, CRAYON, BRUSH, … }`（`Paint.java:394-405`），
每个笔型有 5 个尺寸档位，由 `外部实现` 把 `(type, sizeLevel)` 映射到归一化尺寸
（`Paint.java:154-223`，例如 pencil 为 0.00 / 0.15 / 0.25 / 0.50 / 0.70）。

Scratchmark 目前只有“宿主直接给线宽”，没有档位概念。本规格补一个**只读预置表**：宿主用 `(笔型, 档位)` 查一个归一化比例，
再乘自己的最大宽度，就能得到与其它宿主一致的默认笔宽。

**数值不照抄外部行为观察结果**：参考值已记录在 `docs/research/2026-11-07-oppo-capability-inventory.md`，
但那是样本侧的调参值，按工作台 §6「既有基线结论不能当既定方案」，Scratchmark 用自己的一组分档（单调、可读、有测试）。
宿主仍可完全无视本表、直接给线宽。

- `sm_features()` 新增 bit 11（`SM_FEATURE_BRUSH_PRESET = 1<<11`）。

## 接口

```c
enum {
    SM_BRUSH_PENCIL = 1, SM_BRUSH_MARKER = 2, SM_BRUSH_BALLPEN = 3,
    SM_BRUSH_PEN = 4, SM_BRUSH_ERASER = 5
};
#define SM_BRUSH_LEVELS 5

SmStatus SM_CALL sm_brush_preset(uint32_t kind, uint32_t level, double *out_ratio);
SmStatus SM_CALL sm_brush_preset_width(uint32_t kind, uint32_t level,
    double max_width, double *out_width);
```

- 都是**无句柄纯函数**：无状态、无缓存、失败不写输出。
- `kind` 必须是上面五个之一，`level` 必须在 `1..=5`，否则 `INVALID_ARGUMENT`。
- `out_ratio` 是 `(0, 1]` 内的归一化比例，同一 `kind` 内随 `level` 严格递增。
- `sm_brush_preset_width`：`width = max_width × ratio`；`max_width` 必须有限且落在 `(0, 1e6]`，
  结果必须有限、`> 0`、`<= 1e6`，否则 `INVALID_ARGUMENT`。

## 内置分档（本引擎自有）

| 笔型 | 档位 1..5 的归一化比例 |
| --- | --- |
| `SM_BRUSH_PENCIL` | 0.08 / 0.16 / 0.26 / 0.40 / 0.60 |
| `SM_BRUSH_MARKER` | 0.12 / 0.24 / 0.38 / 0.55 / 0.75 |
| `SM_BRUSH_BALLPEN` | 0.06 / 0.12 / 0.20 / 0.30 / 0.45 |
| `SM_BRUSH_PEN` | 0.10 / 0.20 / 0.32 / 0.46 / 0.62 |
| `SM_BRUSH_ERASER` | 0.08 / 0.13 / 0.20 / 0.29 / 0.40 |

这些是**默认值**，只为让不同宿主在同一档位下看起来一致；笔触纹理、透明度与倾斜映射仍由宿主决定。

## 验收边界

- 五个笔型 × 五个档位全部可查，比例落在 `(0, 1]` 且同一笔型内严格递增。
- 宽度换算：`max_width` 取 1 / 10 / 1e6 三档逐项校验；结果与 `max_width × ratio` 逐位一致。
- 非法 `kind`（0、6、超大值）、非法 `level`（0、6）、非法 `max_width`（0、负、非有限、超 1e6）一律 `INVALID_ARGUMENT` 且不写输出。
- 原 M0–M12 断言与共享夹具不改动，全部保持通过。
- 不实现笔触纹理、透明度档位、倾斜映射、按笔型的平滑差异；不声称这些默认值在真机上是“好看”的。

## 范围与边界

预置表是**便利与一致性**，不是设计正典：它不进快照、不影响渲染、不影响任何几何判定；宿主把自己的档位表存在自己的文档元数据里即可。
