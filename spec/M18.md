# M18 实验规格：宿主内存分配

状态：Canon，仅约束当前实验。SDK 0.1.0，ABI 1，快照格式仍为 1 / 2 / 3；M0–M17 的既有接口与行为保持不变。不承诺稳定发布兼容。

## 背景与能力位

前面所有"输出到宿主缓冲区"的接口（`sm_save` / `sm_copy_strokes` / `sm_cut_strokes` / `sm_read_points` …）
都要求宿主**自己**准备内存。原生宿主有 libc 的 `malloc`，但 WebAssembly 这类宿主只能在自己的线性内存里操作，
拿不到模块内部的分配器——没有这对接口，wasm 宿主根本无法调用快照类接口。

- `sm_features()` 新增 bit 16（`SM_FEATURE_HOST_ALLOC = 1<<16`）。

## 接口

```c
uint8_t *SM_CALL sm_alloc(uint32_t size);
void SM_CALL sm_free(uint8_t *pointer, uint32_t size);
```

- `sm_alloc`：申请 `size` 字节，**8 字节对齐**；`size` 必须落在 `(0, 64 MiB]`，否则返回 `NULL`；
  分配失败同样返回 `NULL`。上限与快照上限一致，避免宿主一次申请过大块。
- `sm_free`：释放 `sm_alloc` 返回的指针；`size` 必须与申请时一致；`pointer == NULL` 是空操作；
  `size == 0` 或超过 64 MiB 时直接忽略（不尝试释放）。
- 两端都不做错误码：分配失败就是 `NULL`，与 C 惯例一致；这两个接口不进入 `guard()`，因为它们不碰文档。
- 分配出来的内存**可以**直接传给任何"输出到宿主缓冲区"的接口；引擎不持有它的所有权。

## 验收边界

- 申请、写入、读回、释放；8 字节对齐。
- `size = 0`、超过 64 MiB、`u32::MAX` 返回 `NULL`。
- 释放 `NULL`、释放时尺寸为 0、尺寸超上限都不 panic（后者直接忽略）。
- 用 `sm_alloc` 拿到缓冲区后调 `sm_save` 写出真实快照，魔数正确。
- 原 M0–M17 断言与共享夹具不改动，全部保持通过。
- 不实现重分配、不实现对齐参数、不实现零初始化；不做内存池。

## 范围与边界

这对接口只解决"宿主没有 malloc"的问题，不改变任何文档语义；原生宿主继续用自己的分配器也完全可以。
