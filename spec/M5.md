# M5 实验规格：沿擦除路径的局部擦除

状态：Canon，仅约束当前实验。SDK 0.5.0，ABI 1，快照格式仍为 1 / 2；M0 / M2 / M3 / M4 的既有接口、原始样本、派生几何、页面标识、视口、命中与整笔擦除行为保持不变（参 `M0.md`、`M2.md`、`M3.md`、`M4.md`）。不承诺稳定发布兼容。

## 能力位

- `sm_features()` 新增 bit 3（`SM_FEATURE_PARTIAL_ERASE = 1<<3`）。
- 新旧宿主按位核对；缺少该位的旧库不得被新绑定误用。

## 擦除路径与删除范围

```c
SmStatus sm_erase_path(SmHandle handle, uint64_t revision,
    const SmPoint *path, uint32_t count, double radius);
```

- 路径是页面坐标下的折线（`SmPoint` 数组），`count >= 1`；`count == 0` 返回 `INVALID_ARGUMENT`。`count` 上限沿用 M0 的批大小 65,536，超出返回 `LIMIT_EXCEEDED`。
- 每个路径点必须有限且绝对值不超过 1e9；`radius` 必须有限且落在 `(0, 1e9]`。违反返回 `INVALID_ARGUMENT`。
- 删除集合是**到该折线距离不超过 `radius` 的闭区域**（包含路径首末点，相邻点之间按线段连接）。半径由宿主按视口换算后传入，引擎不内置设备像素或触控目标尺寸。
- 判定只使用**原始中心线**（与 M4 命中一致），不使用 M2 派生平滑轨迹。
- 只作用于已提交笔划；活动笔划不参与，且不要求文档空闲以外的任何条件。

## 失败与顺序

检查顺序固定为：缓冲区指针 / `count` 上限（M0 规则）→ 活动笔划（`INVALID_STATE`）→ `revision`（`STALE_REVISION`）→ 路径点与 `radius` 校验（`INVALID_ARGUMENT`）→ 预算（`LIMIT_EXCEEDED`）。

- 任一检查失败都不递增 revision、不改变文档、不改变撤销 / 重做历史。
- 成功但**没有任何笔划受影响**时返回 `OK`，同时不递增 revision、不产生历史条目（避免空手势污染历史）。

## 切分语义

- 一个已提交笔划被删除集合切成若干**片段**；片段是新的笔划，宽度与颜色继承原笔划、样本值由原中心线插值得到。
- 片段在笔划列表中占据原笔划的位置，按沿笔划的前后顺序排列；其他笔划的相对顺序不变。因此 z 序由索引顺序保持不变。
- 切点样本的时间为非递减线性插值并取整到整数微秒；两端样本都是 `flags=1` 时插值压力且保持 `flags=1`，否则切点为 `flags=0, pressure=0`（沿用 M0 的样本有效性要求）。
- 整笔都落在删除集合内则整笔消失（产生 0 个片段）；没有任何参数区间被覆盖的笔划完全不变，不做重建。
- 只删除**参数长度大于 0** 的覆盖区间：路径与笔划相切（恰好等于 `radius` 的交点）不切分，避免产生零长度片段。
- 顶点是否被覆盖由相邻两段的判定合并处理；两段因浮点舍入给出不一致结论时，按**被覆盖**处理（多擦一点，不留下误以为已擦除的残迹）。

## 历史与预算

- 一次成功的擦除（含多笔划、多片段）只产生**一个**撤销条目：一次撤销恢复全部被影响笔划及其原索引与 z 序，一次重做再次切分。
- 成功擦除清除重做历史。撤销 / 重做仍只在空闲时可用。
- 资源上限沿用“含历史在内最多 1,000,000 点、100,000 笔划”。切分产生的片段点数计入预算：擦除前的 `retained + 片段总点数` 超过上限时返回 `LIMIT_EXCEEDED`，文档与历史保持原样。
- 快照仍只保存当前已提交笔划（此时为片段），不含撤销 / 重做历史；load 后重做历史清空，载入的片段可按整笔逐笔撤销。
- 擦除不修改页面标识；页面标识规则沿用 M3。

## 范围与验收边界

- 验收覆盖：垂直切分与切点坐标、拐角与单点笔划、顶点被覆盖、整笔删除、相切不切分、未受影响笔划保持不变、一次手势跨多笔划的单一撤销条目、撤销后恢复原索引与 z 序、重做再切分、成功清除重做、失败原子性、预算超限、快照往返与 load 后可撤销。
- 不实现整笔删除以外的选择语义（套索、形状、移动）、预测笔迹、多页管理、Android、MSVC / UWP。
- 切片几何在 f64 下按闭式解计算，同一输入得到同一输出；不声称实机擦除手感、擦除性能或触控目标尺寸已达标。
