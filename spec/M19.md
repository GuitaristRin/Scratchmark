# M19 实验规格：Android JNI 封装

状态：Canon，仅约束当前实验。SDK 0.18.0，C ABI 1 不变；本层只是把既有能力暴露给 JVM，不新增引擎语义。不承诺稳定发布兼容。

## 背景

C ABI 已经完整（bit 0–16），但 Android 宿主是 Kotlin：需要 `System.loadLibrary` 之后能直接调的对象，
以及不需要宿主自己算字节布局的编组。本规格定义 JNI 边界与 Kotlin 侧形态。

## JNI 边界

- 库名 `libscratchmark_jni.so`，类 `com.scratchmark.Native`，导出前缀 `Java_com_scratchmark_Native_`。
- 句柄：`jlong`（对齐 C ABI 的 `u64`），`0` 表示无效。
- 批量数据用 `ByteArray`：样本 32 字节/点、笔刷点 24 字节/点，小端，与 C 结构逐字节一致。
- 状态码与 C ABI 一致：`0` 成功、`1` 参数非法、`3` 状态非法、`5` revision 过期、`6` 超限、`-1` 其它。
- **所有导出都过 `catch_unwind`**：坏参数返回错误码，不允许把宿主进程带走。
- JNI 层不复制引擎逻辑：只调 `scratchmark-core`，避免与 C ABI 行为分叉。

## Kotlin 侧形态

- `Engine`：`AutoCloseable`，`close()` 必须调用（原生侧按句柄持有文档）。
- `state` / `bounds` / `points` / `brushPoints` / `hitTest` / `eraseStroke` / `erasePath` /
  `translateAll` / `copyStrokes` / `cutStrokes` / `paste` / `save` / `load` / `undo` / `redo`。
- `SampleFlags.PRESSURE` / `CUT_END`、`BrushKind`、`Engine.brushPresetRatio/Width`。
- 失败抛 `ScratchmarkException(status)`；不返回隐式的 null/0 语义。

## 验收边界

- `cargo build -p scratchmark-jni` 在 Windows 上通过（证明“能编”），并在三个 Android ABI 上交叉编译通过。
- 每个 ABI 的 `.so` 用 `llvm-nm` 核对：C 层 52 个 `sm_*`、JNI 层 24 个 `Java_com_scratchmark_Native_*`。
- Kotlin 源码给出 AAR 骨架（gradle + manifest + jniLibs 约定），**本机无法 assemble**（缺 gradle/kotlinc）。
- **运行时未验证**：没有设备或模拟器。这一条必须写在文档里，不能含糊成“支持 Android”。
- 不做：Maven 发布、ProGuard 细化规则、多线程/协程封装、Bitmap 渲染示例。

## 范围与边界

JNI 层是**薄适配**：C ABI 仍是唯一真源；Android 专有的东西（Bitmap、触摸事件、页面滚动）都在宿主侧。
