# M16 实验规格：原子剪切

状态：Canon，仅约束当前实验。SDK 0.16.0，ABI 1，快照格式仍为 1 / 2 / 3；M0–M15 的既有接口与行为保持不变。不承诺稳定发布兼容。

## 背景与能力位

参考实现 的选区剪切是**单个原生回调**：`外部实现.选区操作 { Delete, Copy, Cut, Paste, Save }` 与
`onSelectorCut`（`本地参考/本地参考/.../外部实现.java`）。Scratchmark 目前要宿主“先 `sm_copy_strokes` 再
`sm_erase_indices`”，是**两个撤销条目**——撤销一次只回退一半。本规格把剪切合成为一次编辑。

- `sm_features()` 新增 bit 14（`SM_FEATURE_ATOMIC_CUT = 1<<14`）。

## 接口

```c
SmStatus SM_CALL sm_cut_strokes(SmHandle handle, uint64_t revision,
    const uint32_t *indices, uint32_t count,
    uint8_t *out_bytes, uint32_t capacity, uint32_t *out_written);
```

- **一次调用两件事**：先按选区编码剪贴板字节（编码规则与 `sm_copy_strokes` **完全一致**：带轴向的笔划产出格式 3、页面标识为 0，
  否则格式 1），再在**同一个**撤销条目里移除这些笔划。
- 索引规则沿用 M6 / M7 的选区语义：允许乱序，**重复与越界一律 `INVALID_ARGUMENT`**，且不改动文档；`count == 0` 同样 `INVALID_ARGUMENT`。
- 只在空闲时可用（有活动笔划 → `INVALID_STATE`）；`revision` 不匹配 → `STALE_REVISION`。
- 输出容量语义与 `sm_save` / `sm_copy_strokes` 一致：容量不足返回 `BUFFER_TOO_SMALL` 并回报所需字节数，不写数组；
  `out_bytes == NULL && capacity == 0` 只查询长度。**查询模式下不改动文档**（不剪切）。
- 成功时：返回 `OK`、写入字节与 `out_written`、文档笔划数减少、`revision` 递增一次、历史只多一个条目。

## 验收边界

- 单笔 / 多笔（含乱序）剪切：剪贴板内容可被 `sm_paste` 还原回原几何；一次撤销整体恢复（笔划数量、z 序、每个笔划的边界）。
- 带轴向的笔划：剪贴板是格式 3、页面标识为 0，粘贴后轴向保持。
- 失败路径：空列表、重复、越界、过期 revision、活动笔划期间、容量不足、查询模式——文档都不变。
- 查询模式（容量 0）不产生撤销条目、不递增 revision。
- 原 M0–M15 断言与共享夹具不改动，全部保持通过。
- 不做“剪切到系统剪贴板”、不做跨文档剪切、不做剪切后的自动重排；重排仍由宿主用 `sm_translate_all` 或变换完成。

## 范围与边界

剪切是**复制 + 删除的原子合成**，不是新语义：几何判定、命中、快照格式都不变；它只保证撤销粒度与 参考实现 的单回调一致。
