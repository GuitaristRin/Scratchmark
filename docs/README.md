# 文档地图

这个仓库的文档分四类：**要改成什么样**（规格）、**为什么这样**（裁定）、**怎么干活**（开发/架构/验证）、
**现在到哪了**（状态）。先看这张表，再照"阅读顺序"走。

## 阅读顺序

1. [立项任务卡](PROJECT_BRIEF.md) —— 阶段目标与已确认范围。
2. [架构](ARCHITECTURE.md) —— 分层、数据模型、不变量、快照格式、能力位、错误码。
3. [开发手册](DEVELOPMENT.md) —— 环境、四条门、四平台脚本、提交与证据约定、已踩过的坑。
4. [验证矩阵](VERIFICATION.md) —— 哪些真跑过、哪些只编过、哪些没验证、怎么补。
5. [平台与封装库](PLATFORMS.md) —— Windows / WASM / Android / Linux / .NET 的产物与验证等级。
6. [接口索引](API.md) + [C 接口声明](../include/scratchmark.h) —— 52 个导出怎么分组、线程与所有权约定。
7. 具体能力看 `spec/M<n>.md`（行为真源）与 `docs/IMPLEMENTATION_M<n>.md`（当轮边界与验收）。

宿主接入看 [HOST_INTEGRATION.md](HOST_INTEGRATION.md)，SDK 打包与验收看 [SDK_README.md](SDK_README.md)。

## 维护规则

1. 新规格 → `spec/M<n>.md`；当轮边界 → `docs/IMPLEMENTATION_M<n>.md`；两个都要在 [README](../README.md) 与本文档的
   分类表里出现。
2. 裁定只追加 `D<n>`；状态只追加日期小节。
3. 文档里的数字必须能在当次工具输出里找到；不确定就写"未验证"。
4. 接口变了先改 `include/scratchmark.h` 与 `spec`，再改 `API.md` 的类型分组。
