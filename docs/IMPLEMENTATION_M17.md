# M17 - 擦除切点标记任务卡

状态：Canon（本阶段边界）。日期：2026-11-07。前置：M0–M16 已合入并推送（`90e4d62`）。行为真源为先行编写的 `spec/M17.md` 与 C 头文件。
触发来源：用户两次反馈“局部擦除看起来很奇怪”，以及清单第六节的证据——参考实现 的擦除是几何标记 + 渲染侧丢弃，
圆缺口来自渲染而不是位图。因此补“切点标记”，让宿主能把切出来的端点画成圆头/缺口。

## 目标与真源

`SmSample.flags` 从“只能 0/1”扩成位域：bit0 压力、bit1 擦除切点、其余位必须为 0。
引擎在 `sm_erase_path` 切分时给**切出来的端点**打 bit1；原始端点不打；整笔删除、变换、复制粘贴、快照往返都原样保留；规整归零。
**不新增快照格式**（`flags` 本来就在样本里），也不新增读取导出（走 `sm_read_points`）。

## 本轮范围

1. 核心：`Sample::is_valid` 改成位域校验；擦除切分时给切点打标；其余编辑路径保留/归零标记。
2. 写入通道只允许 `flags` 为 0 / 1（`sm_append` / `sm_append_axes` 拒绝伪造切点）。
3. C ABI：新增 features bit 15；头文件写明位域语义；不新增导出。
4. C#：`Sample` 增加 `IsCutEnd` 便捷判定，示例演示“擦完读回切点标记”。
5. C 示例、SDK 构建与验收脚本同步更新。
6. 便签验证器：渲染时对带标记的端点画圆头，加大块擦除演示，用于肉眼对比“平口 vs 圆缺口”。

## 验收

- 切分后切点带 bit1、原始端点不带、片段内部不变；多片段时每处切口都带标记。
- 变换 / 平移 / 复制粘贴 / 快照往返保留标记；规整归零。
- `sm_append` 传 `flags = 2/3` 被拒；载入越界 flags 或 bit0 未置位却带压力 → `INVALID_DATA`。
- 既有 M0–M16 断言与共享夹具不改动，全部保持通过。
- fmt / workspace test / clippy -D warnings / release 通过；SDK 独立目录 C 动态、静态与 C# 宿主实际运行通过。
- 验证器自检覆盖切点标记读取，并截图对比观感。

## 止损与边界

不做像素擦、缺口几何、端帽形状；不改快照格式；不修改 PezMax-One、不建 submodule；本轮**不推送**，等用户指示。
