# M1 - 原生宿主适配验证任务卡

状态：Canon（本阶段实施边界）。日期：2026-11-04。授权：用户已确认“按任务卡继续”。

## 目标与真值

将 M0 的接口审查推进到实际跨语言调用。沿用 D1/D2 的纯引擎、Rust 核心与 C# / Kotlin 原生适配方向；本阶段不拥有应用窗口、不验证书写手感。

行为真源为 [M0 规格](../spec/M0.md) 与 [C 头文件](../include/scratchmark.h)；[接口审查](M1_INTERFACE_REVIEW.md) 只作参考，建议不自动成为契约。适配层的实验契约先写规格，再写代码。

## 本轮范围

1. Windows x64：用现有 .NET 9 SDK 提供无第三方包的 C# 实验适配层与控制台宿主；实际加载 SDK 中的 DLL，验证结构体布局、批量输入、活动笔迹、提交 / 取消、撤销重做与快照恢复后继续编辑。
2. C# 对每个文档协调调用与 Dispose，保留 uint64 句柄的完整位宽；不能直接把数值 ID 收窄成平台指针。封装版本检查、状态码与 INTERNAL 后的停用 / 销毁策略；保留 revision 门控。
3. 宿主从无引擎源码的 SDK 目录运行，只依赖打包二进制与头文件契约；验证固定夹具与快照字节，不能只做自写自读。
4. Android 同等优先保留：先核查已有 SDK/NDK、Rust target 与 Kotlin 工具链。工具链齐备时，再落实有界 JNI/Kotlin 调用验收；缺失时列明所需组件、构建命令与未验证项，不用 Windows 结果替代 Android 证据。

## 验收

- 核心 fmt / test / clippy 及 Windows SDK 原生宿主检查仍通过。
- C# 宿主实际运行，覆盖完整编辑闭环、布局、失效句柄、错误批次原子性、STALE_REVISION、容量不足与损坏快照不替换原文档。
- 快照与只读共享夹具一致；显式 Dispose 可重复调用，释放后操作明确失败。
- 独立目录运行，保存完整命令、工具链身份与检查数量。
- Android 构建、JNI 调用与设备体验分别报告；没有运行就明确标为未验证。

## 止损与边界

不改 M0 ABI、核心行为或既有裁定，不新增第三方依赖，不安装大型工具链，不操作真实设备，不修改 PezMax-One，不上传产物，不推送。若发现必须改 ABI 或 Android 需安装组件，先记录具体缺口与可审查方案再请求决定。

本机有 .NET SDK 9.0.316、GCC 16.1.0 与 JDK 17。初次工具链查找遗漏 D 盘；用户指出后已确认 `D:/Applications/AndroidSDK` 与 Studio 内置 Kotlin 2.3.10 可用，Gradle 已缓存。Android Rust target 未安装，NDK 尚未定位；具体证据与待授权组件方案见 [前置核查](ANDROID_PREREQUISITES.md)。此为环境核查，不构成 Android 适配验证。
